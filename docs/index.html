How it works

Four stages, all on your machine

Every stage is idempotent and its state lives in a local SQLite ledger, so a run can be killed and restarted and it picks up where it stopped.

01 / INGEST

Fetch the source

A YouTube link or a local file. Downloads at 1080p by default, because a 9:16 crop keeps only 56% of the width and 720p would mean upscaling 2.7×.

02 / UNDERSTAND

Find the moments

Whisper produces word-level timings; a local Ollama model reads the transcript and scores candidate clips. Or skip the words entirely and cut on shot changes.

03 / RENDER

Frame and caption

Crops that follow the speaker and step at scene cuts, stacked split for two-person scenes, five caption styles burned in from the word timings.

04 / PUBLISH

Post, or don't

Optional upload to YouTube, Instagram and TikTok with per-platform caps and spacing. Nothing leaves your machine unless you ask for it.

Why this one

The parts other clippers skip

Framing

Card layout

A 9:16 crop throws away 44% of a 16:9 frame. Card mode keeps all of it as an inset panel over a blurred backdrop — positioned clear of the like and share buttons rather than running underneath them.

Framing

Crops that respect cuts

The crop follows the speaker, then steps at a shot change instead of gliding across it. Two faces on screen become a stacked split automatically.

Music

Beat-cut edits mode

Supply a track and a folder of footage; onset detection finds the tempo and cuts the shots to it, with transitions, grading and lyrics on screen. Cuts land within 3 frames of the beat.

Workflow

Campaigns and payouts

Group sources, styling and posting rules per campaign, record the rate, and get every posted link in a CSV ready for clipping-program submission forms.

Privacy

Nothing phones home

Whisper and Ollama both run locally. There is no default hosted endpoint — hosted models are opt-in and refuse to run without a key you provide.

Control

Style it per run

Captions, title card, framing and clip-selection strategy are all flags, not a rebuild. Re-render queued clips in a new style without re-downloading or re-transcribing.

Install

Three commands

macOS and Linux. Python 3.11+, and an ffmpeg built with libass — the installer checks for both and tells you exactly what is missing.

$ git clone https://github.com/umschaudhary/verticlip && cd verticlip
$ ./install.sh                      # ffmpeg, venv, dependencies
$ ollama pull qwen2.5:7b-instruct   # the highlight picker

$ ./clip                            # asks for a URL and the rest

A desktop app is not ready yet

This is a CLI today. A packaged macOS build is planned, and the terminal path will stay — it is how it runs on Linux and under cron.

Status

What works, and what doesn't

Written plainly, because finding this out after cloning is worse than reading it here.

Known limits

  • Instagram and TikTok publishers are written but unproven — no live upload has been made. YouTube has.
  • Facecam layout — screen-share with a corner camera is not detected yet.
  • MediaPipe aborts on some macOS builds, so face detection falls back to OpenCV cascades. A subprocess probe refuses it rather than crashing a render.
  • Speed — a 29-minute source takes about 16 minutes end to end, most of it Whisper.

Clip only what you have the right to clip

Most YouTube videos are all-rights-reserved. Re-uploading someone else's work can earn a Content ID claim or a copyright strike, and "a script did it" is not a defence.

Legitimate sources: your own footage, Creative Commons material, content you have written permission for, and creator clipping programs that explicitly grant the right to clip a specific asset — which is exactly what the campaign system is built for.
